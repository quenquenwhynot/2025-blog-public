# 数据库事务：回滚只能撤销尚未提交的那一段

事务实验先删除几条记录，再分别执行回滚和提交。SQL 本身很短，却很适合建立一个基础概念：回滚作用于当前尚未提交的事务，不是数据库的无限撤销键。

## 用一条时间线理解边界

可以在练习库中创建一张简单的笔记表，再观察同一事务内的变化：

```sql
BEGIN;
UPDATE study_note SET status = 'archived' WHERE id = 1;
SELECT id, status FROM study_note WHERE id = 1;
ROLLBACK;
SELECT id, status FROM study_note WHERE id = 1;
```

这里假定表和记录已经存在。第一次查询能看到本事务的修改，回滚后再查，该次修改被撤销。若改成 `COMMIT`，事务就结束了，之后单独执行 `ROLLBACK` 不会把这次已提交的更新恢复。

需要恢复已提交内容时，应根据业务设计新的更正或补偿操作；这和撤销一个未提交事务是不同的事情。

## 两个连接才能看出并发问题

事务隔离的现象往往需要同时打开两个会话：一个执行修改但暂不提交，另一个查询，再观察提交前后变化。只在一个窗口里顺序执行，很容易把自己的修改误当成所有连接都能立即看到的结果。

实验记录应写明隔离级别、语句顺序和提交位置。否则两张查询截图即使结果不同，也很难解释原因。

## 不把旧讲义里的概括直接当结论

原材料有些描述针对特定教学安排，整理时不沿用“只支持两种隔离等级”这类笼统说法。更稳妥的是围绕本次实际设置和观察说明结果。

这次实验最有用的习惯，是在每组 SQL 前先标出事务从哪里开始、在哪里结束。边界清楚了，很多看似矛盾的查询结果就有了解释。
