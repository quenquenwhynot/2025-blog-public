初学 C 语言时，最容易产生一种错觉：老师讲的分支和循环都听懂了，自己写题却总差一点。回看数组和函数实验，很多错误并不来自复杂算法，而是没有把变量在每一步的变化想清楚。

## 先写出一个很小的输入

求一组数的平均值，不必上来就输入几十个数。先用 `2、4、6`，手算总和是 12、个数是 3、平均值是 4。再逐轮记录 `i` 和 `sum`，很快就能看出循环是多跑了一次，还是少读了一个数。

```c
int values[] = {2, 4, 6};
int n = 3;
double sum = 0;
for (int i = 0; i < n; ++i) {
    sum += values[i];
}
double average = sum / n;
```

这段示例只处理非空数组；如果允许用户输入个数，就要先确认个数大于零。让总和使用浮点类型，也避免整数除法把小数部分直接截掉。

## 把“程序不对”变成一个具体问题

检查时可以沿着三步走：输入实际读到了什么，循环里哪个变量改变了，输出表达式用了哪个值。需要时临时打印中间结果，确认后再去掉。

遇到结果差一点，不要立刻重写整个程序。先看循环边界、初始值、数据类型。这三个地方的错误，在刚开始练习时远比算法本身更常见。

对我来说，入门阶段值得反复练的能力，是把一轮循环解释清楚。能在纸上走完三个元素，才更容易相信程序处理三百个元素时也遵守同一套规则。
