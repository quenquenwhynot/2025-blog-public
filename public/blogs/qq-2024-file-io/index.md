# 文件读写：让程序记得上一次的结果

文件输入输出和之前的练习相比，多了一个很直观的变化：程序结束之后，数据还可以留在磁盘上。下次运行时，不必重新输入所有内容。

不过，“能写进文件”只是第一步。完整的过程还包括路径是否正确、打开是否成功、读到了多少内容，以及发生错误后怎样结束。

## 用读取结果控制循环

```c
FILE *file = fopen("numbers.txt", "r");
if (file == NULL) {
    perror("numbers.txt");
    return 1;
}

int value;
while (fscanf(file, "%d", &value) == 1) {
    printf("%d\n", value);
}
fclose(file);
```

示例需要包含 `stdio.h` 并放进主函数。这里判断的是这一次是否真的读到了一个整数，而不是提前猜测文件是否已经结束。正式处理数据时，还应区分正常读到末尾、格式不符合预期和实际读写错误。

## 路径是相对于哪里

相对路径通常相对于进程当前工作目录，并不一定是源代码所在目录。编辑器能找到文件，程序却找不到，很可能是启动位置不同。遇到问题时，先检查实际工作目录，再确认文件名和扩展名。

写入模式也要看清：`w` 会在成功打开已有文件时截断内容，`a` 则追加。对需要保留的记录，不能把“重新生成”和“继续添加”混为一谈。

## 留一个能恢复的版本

学习程序可以先从文本文件开始，格式简单，也方便肉眼核对。但如果是重要内容，覆盖前保留备份会省掉许多麻烦。写入失败时也不能只输出一句“保存成功”。

文件实验让我意识到，程序和外部世界开始接触以后，很多条件都不由代码单方面决定。承认这些失败可能，并把它们处理清楚，也是程序的一部分。
