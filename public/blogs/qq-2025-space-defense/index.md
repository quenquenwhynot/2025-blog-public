“太空保卫战”的项目说明很直白：方向键位控制飞机，空格发射，生命耗尽后结束，还可以暂停和重新开始。它的运行环境是 JavaFX、JDK 21 和 Maven。

README 里留下了一句很有现场感的话：因为对 `resources` 下目录的理解不够清楚，找图片和 FXML 的路径花了很长时间。相比功能清单，这个问题更值得单独记下来。

## 源码目录和资源目录有不同用途

Java 源码按包组织，图片、FXML 等资源则应以打包后可定位的路径读取。编辑器里能看到一张图片，不代表运行时能按同一条磁盘路径读到它。

桌面开发时容易把“当前项目文件夹”当成永远存在的前提。但程序打成包以后，目录和读取方式可能不同。应尽早检查构建产物中的资源是否真的被包含。

## 加载失败先检查返回值

使用类路径资源加载时，先确认得到的 URL 或流是否为空，再继续创建图片或界面。这样错误会停在更接近原因的位置，而不是在后面出现一个难以理解的空指针异常。

同时检查路径开头是否表示根、文件名大小写是否一致、构建配置是否复制资源。不要一边改目录一边改代码，最后不知道究竟是哪一步起了作用。

## 游戏还有状态需要整理

开始、运行、暂停、结束、重开应有明确状态。重新开始时，不只重置分数，还要清理旧子弹、敌人和计时状态。否则看起来重新开始了，旧一局的数据仍可能继续影响画面。

这份小项目提醒我：能把角色画出来很有成就感，而让它在不同启动方式下稳定运行，还需要理解工程目录、资源加载和生命周期。
