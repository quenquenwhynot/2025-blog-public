当程序开始同时处理编号、名称和数值，继续维护好几个数组就有些费力。每次排序都要记得一起交换，少动一个数组，记录就错位了。结构体给出了一个自然的办法：把描述同一个对象的数据放在一起。

```c
struct Reading {
    int id;
    char name[32];
    double value;
};

struct Reading item = {1, "sample", 3.5};
```

这里的重点并不是多了一个关键字，而是可以用 `item.id` 和 `item.value` 表达“这条记录的哪个部分”。代码和要描述的东西靠得更近了。

## 先定义一条记录，再考虑很多条

如果一条记录代表一次测量，就要先决定哪些字段必须存在、名称最多多长、数值能否缺失。随后再用结构体数组组织多条记录，排序时交换整条记录，减少字段之间失去对应关系的机会。

函数也可以围绕这条记录设计，例如检查它是否有效、输出一条记录、比较两条记录。这样以后加字段时，更容易找到受影响的位置。

## 指针成员不等于复制内容

带字符数组的结构体和带字符指针的结构体，使用起来并不完全相同。复制一个指针成员，只是复制地址，不会自动复制它指向的数据。如果两个对象共享一块动态内存，就还要考虑由谁管理和释放。

初学时不必一次掌握所有复杂情况，但应该知道“看起来复制成功”和“拥有独立内容”之间还有区别。

结构体这一章让我开始习惯先想数据长什么样，再写处理它的循环。数据组织清楚了，很多函数就不必接收一长串互相对应的参数，程序也更容易解释。
