搭建 quenquen 博客的过程，不只是把页面部署出去。仓库保存代码和内容，构建生成可运行的站点，托管服务负责响应请求，域名则给访问者一个更容易记住的入口。

## 先弄清修改会经过哪里

这个博客以 GitHub 仓库作为内容与代码来源，使用 Cloudflare Workers 的构建部署流程。项目中保留的命令是：

```text
pnpm run build:cf
pnpm run deploy
```

仓库提交成功，只代表版本已经保存；构建完成和实际页面出现新内容，还需要分别确认。自动部署方便，但它仍然是一条有多个阶段的链路。

## 域名是入口，不是全部服务

选择域名时，应同时看首年价格、续费与附加项目。购买之后，还要配置解析或站点绑定，并检查实际访问。表单里填写根域名时，不把协议和文章路径混进去。

我不想在回顾里保留已经过期的促销价格。域名、证书和访问状态，应以当时实际操作结果为准，而不是根据一张“可购买”的截图宣布完成。

## 模板改成自己的站点，需要处理细节

导航要能在电脑、窄窗口和手机上使用，文章页要有清楚的返回入口。个人资料、示例文章和外部链接也值得逐项检查。保留参考作者文章时，应继续保留来源，不能只改标题和署名。

这次建站的技术基础来自 [YYsuni 的开源博客项目](https://github.com/YYsuni/2025-blog-public)。在它的基础上逐步调整布局、写作和内容，才慢慢有了自己的使用方式。

最有成就感的不是配置表全部填满，而是打开实际网站时，能从首页走到文章，再顺畅回到自己想去的位置。
