# Dijkstra 实验：最短距离之外，别忘了不可达

最短路径实验采用邻接矩阵存图，从指定源点计算到其他顶点的距离。核心过程可以概括为：在未确定的顶点里选距离最小者，再尝试用它改善其他顶点的距离。

## 先确定适用条件

Dijkstra 适用于边权非负的图。这个条件和算法“选出的最小距离可以确定下来”的思路有关。面对负权边时，不能因为样例刚好通过，就继续套用同一结论。

假设有三条边：A 到 B 是 4，A 到 C 是 1，C 到 B 是 2。从 A 开始，先发现 C 更近，再通过 C 把 B 的距离从 4 改为 3。这一步改善就是松弛。

## 没有找到候选点，也是一种正常结果

图不一定连通。如果剩下顶点的距离都还是无穷大，就没有必要继续选点。实现里要检查是否真的找到了有效顶点，不能把 `-1` 当作数组下标使用。

无穷大通常用一个足够大的哨兵值表示，但它仍然是有限整数。计算 `distance[u] + weight` 前，先确认两项有效，并考虑数值范围，避免哨兵值参与运算造成溢出。

## 想输出路线，就还要记录前驱

距离数组只能回答“多远”。如果要回答“怎么走”，在更新距离时还应保存前驱顶点。最后从目标反向追溯到源点，再把顺序倒过来。

测试时可以准备一个连通小图、一个包含不可达顶点的图和一个源点到自身的情况。零权边也要与“无边”的表示区分开。

这次实验值得留下的，不只是算法步骤，还有对失败条件的处理。不可达不意味着程序坏了；能够清楚地说明不可达，才是一个完整的结果。
