# 没有可用 CUDA 时，我怎样整理 GemDepth 的最小运行路径

GemDepth 的本地入门文档记录过一次 CPU 适配：环境里没有可用 CUDA，于是改用 CPU 版依赖，并把视频处理规模压低，先验证输入到输出的最小链路。

## 先确认正在使用哪个 Python

项目依赖与系统 Python 混在一起时，安装和运行可能根本不是同一个环境。先使用项目虚拟环境里的解释器，再检查 PyTorch 版本和设备可用性：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

`False` 表示当前 PyTorch 环境无法使用 CUDA，不能单凭这一个值判断机器所有硬件情况。显存和普通内存也不是一回事，文档中的 GPU 显存需求不能直接套用到 CPU 内存。

## 把输入缩到能检查的大小

留存方案从少量帧、较低采样帧率和较小输入尺寸开始，并调整推理窗口及相邻窗口的重叠。它们会影响计算量，也可能影响结果质量，不能把最小配置当成官方默认配置。

本地还补充了 CPU 依赖文件和运行脚本，处理 GPU 专用计算路径不适用的问题。只改一个设备字符串，未必足以让所有算子都兼容 CPU。

## 有视频文件，还要打开检查

旧文档记录了最小测试输出。进一步检查应看视频是否可播放、处理帧数是否符合预期、深度可视化是否与输入对应。看到输出文件名，只能说明流程产生了文件，不能证明估计精度。

这篇依据留存的运行文档回顾，没有在本次整理中重新执行模型。更换依赖、模型版本或设备后，需要重新验证；原始方法与配置仍应参考[官方仓库](https://github.com/Yuecheng919/GemDepth)。先跑通一小段，再逐项扩大输入，是这次实践最可复用的部分。
